# 醫療保健：臨床輔助與醫療文件處理

> **一句話**：針對醫療保健場景，提供從醫療文件處理到臨床決策輔助的 AI 導入路徑，嚴格遵循患者安全原則。

---

## 領域概述

### 目標讀者

- 醫療資訊主管（CIO/CMIO）
- 醫療科技公司產品經理
- 健康保險業務分析師
- 醫療品質管理人員

### 核心問題

| 問題 | 傳統做法 | AI 可解決程度 |
|------|---------|--------------|
| 病歷文件整理 | 人工輸入/整理 | **高**（自動化摘要、分類） |
| 醫療編碼（ICD/CPT） | 專業人員編碼 | **中高**（輔助建議） |
| 文獻檢索 | 手動 PubMed 搜尋 | **高**（RAG + 醫學知識庫） |
| 患者問答 | 客服/護理師回答 | **中**（常見問題，需審核） |
| 臨床試驗篩選 | 人工比對條件 | **高**（自動比對 criteria） |
| 藥物交互作用 | 查詢資料庫 | **中高**（需驗證來源） |

### 重要聲明

```
⚠️ 醫療 AI 應用聲明

本領域包描述的 AI 應用嚴格限於「輔助」用途：

1. **非診斷工具**：AI 產出不構成醫療診斷
2. **專業覆核必須**：所有結果需經執業醫療人員審核
3. **患者安全優先**：任何涉及患者安全的決策必須由人類做出
4. **法規遵循**：需符合 HIPAA、FDA 等相關法規要求
5. **責任歸屬**：AI 系統為輔助工具，醫療決策責任仍由醫療人員承擔

高風險場景（診斷、治療建議）不建議使用通用 LLM，
應採用經過驗證的醫療專用系統。
```

## 風險分級

### AI 應用風險等級

| 風險等級 | 定義 | 範例 | AI 適用性 |
|----------|------|------|-----------|
| **低風險** | 行政/文書輔助 | 掛號問答、預約管理 | 適合 |
| **中風險** | 資訊整理/建議 | 病歷摘要、編碼建議 | 需審核 |
| **高風險** | 臨床輔助 | 藥物建議、檢查解讀 | 嚴格限制 |
| **極高風險** | 診斷/治療決策 | 疾病診斷、治療計畫 | 不建議通用 LLM |

## 導入路徑（Roadmap）

### Quick Win（2-4 週）

**目標**：從低風險場景驗證可行性

| 項目 | 做法 | 成功標準 |
|------|------|---------|
| **患者常見問答 PoC** | RAG + 衛教文件 | 100 題測試，相關率 >85% |
| **病歷摘要 PoC** | 門診病歷摘要 | 醫師滿意度 >70% |

**測試資料建議**：
- 使用去識別化（de-identified）資料
- 準備 50+ 常見問題作為測試集
- 準備 20+ 去識別化病歷作為摘要測試

**預算估算**：
- API 費用：$100-300
- 人力：2 人 × 2 週
- 資料準備：依去識別化需求

**Gate**：
- [ ] 常見問答準確率 > 85%
- [ ] 病歷摘要 Faithfulness > 85%
- [ ] 無患者隱私資料外洩
- [ ] 醫療專業人員覆核通過

---

### Pilot（6-12 週）

**目標**：小規模驗證，建立覆核流程

| 項目 | 做法 | 成功標準 |
|------|------|---------|
| **患者問答上線** | 整合到官網/App | 使用率 >30%，滿意度 >75% |
| **病歷摘要工具** | 內部試用 | 醫師採用率 >50% |
| **醫療編碼輔助** | 編碼建議系統 | 建議採用率 >60% |

**關鍵活動**：
1. 建立醫療專業人員覆核流程
2. 整合到現有 HIS/EMR 系統
3. 建立錯誤回報和修正機制
4. 收集使用者回饋

**合規檢查**：
- [ ] HIPAA 合規評估
- [ ] 資料安全審查
- [ ] 使用者同意機制
- [ ] 稽核日誌建立

**預算估算**：
- API 費用：$500-1,500/月
- 系統整合：依現有架構
- 人力：3-4 人 × 8 週

**Gate**：
- [ ] 患者問答滿意度 > 75%
- [ ] 醫師工具採用率 > 50%
- [ ] 無嚴重錯誤（影響患者安全）
- [ ] 合規檢查通過

---

### Production（持續運營）

**目標**：穩定運行，擴展場景

| 項目 | 做法 | 成功標準 |
|------|------|---------|
| **全面部署** | 擴展到更多科別/分院 | 穩定運行 |
| **持續監控** | 品質指標監控 | 指標不下滑 |

## 合規要求

### HIPAA 遵循（美國）

| 要求 | 說明 | AI 系統考量 |
|------|------|------------|
| **PHI 保護** | 保護患者健康資訊 | 資料加密、存取控制 |
| **最小必要原則** | 僅存取必要資訊 | 限制 AI 存取範圍 |
| **稽核追蹤** | 記錄所有存取 | 完整日誌 |
| **業務夥伴協議** | 第三方合規 | API 供應商需簽 BAA |

### 個資法遵循（台灣）

| 要求 | 說明 | AI 系統考量 |
|------|------|------------|
| **特種個資** | 醫療資料為特種個資 | 需明確同意 |
| **目的限制** | 依蒐集目的使用 | 限定 AI 使用範圍 |
| **安全維護** | 適當安全措施 | 加密、存取控制 |

### FDA 軟體醫材（SaMD）考量

```
⚠️ FDA 規範提醒

若 AI 系統用於：
- 疾病診斷
- 治療建議
- 疾病預防

可能被歸類為軟體醫材（SaMD），需要：
- FDA 510(k) 或 De Novo 審查
- 臨床驗證
- 品質管理系統

通用 LLM API 通常不具備此等認證。
```

## 資料安全考量

### 資料處理原則

| 階段 | 考量 | 建議做法 |
|------|------|---------|
| **收集** | 最小化原則 | 僅收集必要資訊 |
| **傳輸** | 加密傳輸 | TLS 1.3+ |
| **處理** | 去識別化 | 移除 18 項 HIPAA 識別碼 |
| **儲存** | 加密儲存 | AES-256 |
| **API 呼叫** | 資料外洩風險 | 考慮本地部署或 BAA |

### 去識別化（De-identification）

HIPAA Safe Harbor 方法需移除的 18 項識別碼：

1. 姓名
2. 地理資訊（小於州）
3. 日期（年除外）
4. 電話號碼
5. 傳真號碼
6. 電子郵件
7. 社會安全號碼
8. 病歷號
9. 健康保險號
10. 帳戶號碼
11. 證照號碼
12. 車輛識別碼
13. 設備序號
14. 網址
15. IP 位址
16. 生物識別
17. 全臉照片
18. 其他唯一識別碼

## 風險與緩解

| 風險 | 影響 | 緩解措施 |
|------|------|---------|
| **幻覺/錯誤資訊** | 患者安全 | 強制標註來源、專業覆核 |
| **隱私外洩** | 法律/信任 | 去識別化、本地部署 |
| **過度依賴** | 專業判斷弱化 | 明確輔助定位、培訓 |
| **偏見** | 不公平醫療 | 持續監測、多元測試集 |
| **合規違反** | 法律風險 | 定期合規審查 |
| **責任歸屬不清** | 糾紛 | 明確責任歸屬文件 |
