# 電商：產品問答與推薦自動化

> **一句話**：針對電商場景，提供從產品問答到智能推薦的完整 AI 導入路徑。

---

## 領域概述

### 目標讀者

- 電商平台產品經理 / 技術主管
- 品牌電商數位轉型負責人
- 客服部門主管

### 核心問題

| 問題 | 傳統做法 | AI 可解決程度 |
|------|---------|--------------|
| 產品規格查詢 | 人工查詢/FAQ 頁面 | **高**（RAG 準確回答） |
| 產品比較 | 人工整理比較表 | **高**（自動生成比較） |
| 購買建議 | 客服經驗判斷 | **中高**（基於需求推薦） |
| 庫存/物流查詢 | 系統查詢 | **高**（API 整合） |
| 退換貨問答 | 客服處理 | **高**（政策問答） |
| 個性化推薦 | 推薦引擎 | **中**（LLM 輔助解釋） |

## 導入路徑（Roadmap）

### Quick Win（1-2 週）

**目標**：驗證產品問答可行性

| 項目 | 做法 | 成功標準 |
|------|------|---------|
| **產品問答 PoC** | 熱銷 Top 100 產品 + RAG | 100 題測試，相關率 >80% |
| **政策問答 PoC** | 退換貨政策文件 + RAG | 50 題測試，準確率 >90% |

**資料準備**：
- 產品目錄（名稱、規格、價格、描述）
- 退換貨政策文件
- 常見問題 FAQ

**預算估算**：
- API 費用：$50-100
- 人力：1-2 人 × 1 週

**Gate**：
- [ ] 產品問答相關率 > 80%
- [ ] 政策問答準確率 > 90%
- [ ] 無嚴重錯誤（價格、規格錯誤）

---

### Pilot（4-8 週）

**目標**：小規模實際運行，驗證用戶接受度

| 項目 | 做法 | 成功標準 |
|------|------|---------|
| **產品問答上線** | 整合到商品頁/客服系統 | 使用率 >30%，滿意度 >70% |
| **庫存查詢整合** | LLM + 庫存 API | 準確率 100% |
| **多語言支援** | 熱門語言翻譯 | 品質抽檢通過 |

**關鍵活動**：
1. 整合到現有客服/商品頁
2. 連接庫存/物流 API
3. 建立人工覆核流程
4. 收集用戶回饋

**預算估算**：
- API 費用：$300-800/月
- Vector DB：$0-100/月
- 人力：2-3 人 × 4 週

**Gate**：
- [ ] 用戶滿意度 > 70%
- [ ] 無因 AI 錯誤導致的投訴
- [ ] 客服工單減少 > 20%

---

### Production（持續運營）

**目標**：全面部署，持續優化

| 項目 | 做法 | 成功標準 |
|------|------|---------|
| **全產品覆蓋** | 全目錄建入 RAG | 覆蓋率 100% |
| **智能推薦** | 對話式需求收集 + 推薦 | 轉換率提升 |
| **售後自動化** | 退換貨流程自動化 | 處理時間減少 50% |
| **多語言全面** | 全語言支援 | 國際訂單覆蓋 |

**預算估算**：
- API 費用：$1,000-5,000/月（依流量）
- 維護人力：0.5-1 FTE

## 電商專屬考量

### 產品資料管理

| 資料類型 | 更新頻率 | 處理方式 |
|----------|---------|---------|
| **產品規格** | 不定期 | 增量更新 Embedding |
| **價格** | 頻繁 | 即時 API 查詢（勿 cache） |
| **庫存** | 即時 | 即時 API 查詢 |
| **促銷活動** | 頻繁 | 定期更新 + 有效期標記 |
| **退換貨政策** | 低頻 | 版本控制 |

### 價格敏感處理

```
⚠️ 重要：價格資訊處理規則

1. 價格永遠從 API 即時查詢，不可 cache
2. 促銷價格需標明有效期
3. 不同通路價格可能不同，需確認來源
4. 價格變動需有告知機制
```

### 庫存整合

```
用戶：「這款有現貨嗎？」

推薦流程：
1. 解析產品識別（SKU/名稱）
2. 呼叫庫存 API 查詢
3. 回覆庫存狀態 + 預計到貨時間（如缺貨）
4. 提供替代推薦（如缺貨）
```

## 風險與緩解

| 風險 | 影響 | 緩解措施 |
|------|------|---------|
| **價格錯誤** | 法律糾紛、損失 | 即時 API、不 cache 價格 |
| **規格錯誤** | 退貨、客訴 | RAG + 人工抽檢 |
| **推薦偏差** | 用戶不信任 | 解釋推薦理由 |
| **庫存不同步** | 超賣 | 即時 API 查詢 |
| **競品比較** | 法律/商業風險 | 限制比較範圍 |
| **承諾超出政策** | 執行困難 | 政策邊界明確化 |

詳見：[[幻覺與可追溯性_Hallucination-Grounding]]、[[資料治理與權限_Data-Governance-Access-Control]]

## 對話流程設計

### 產品問答流程

```
用戶：「iPhone 15 Pro 和 15 Pro Max 有什麼差別？」

AI 流程：
1. [意圖識別] 產品比較
2. [RAG 檢索] 查詢兩款產品規格
3. [生成回答] 結構化比較表
4. [價格查詢] 即時 API 查詢價格
5. [回覆] 規格比較 + 價格 + 購買連結

回覆範例：
「iPhone 15 Pro 和 15 Pro Max 的主要差異如下：

| 項目 | 15 Pro | 15 Pro Max |
|------|--------|------------|
| 螢幕 | 6.1 吋 | 6.7 吋 |
| 電池 | 較小 | 較大 |
| 相機 | 5x 光學變焦 | 5x 光學變焦 |
| 價格 | $XX,XXX 起 | $XX,XXX 起 |

需要我幫您確認庫存嗎？」
```

### 購買建議流程

```
用戶：「想買一台筆電工作用」

AI 流程：
1. [需求收集] 「請問主要用途是？預算範圍？」
2. [用戶回答] 「寫程式、偶爾修圖，預算 4 萬」
3. [推薦生成] 基於需求篩選 + 排序
4. [回覆] 推薦 2-3 款 + 理由

回覆範例：
「根據您的需求（程式開發 + 修圖，預算 4 萬），推薦以下選擇：

1. **MacBook Air M3** - $38,900
   - 適合：輕便、電池續航佳
   - 注意：13.6 吋螢幕較小

2. **ASUS Zenbook 14** - $35,900
   - 適合：Windows 生態、性價比高
   - 注意：顯卡較弱

需要更詳細的比較嗎？」
```
