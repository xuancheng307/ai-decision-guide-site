# 小公司 AI 導入 SOP：從 0 到 1

> 給沒有 AI 團隊的中小企業，一步步把 AI 用起來的實戰指南。

---

## 導入心法（先讀這個）

### 1. 不要想一次到位
- 先做一個小的、可驗證的 PoC
- 成功了再擴展，失敗了成本也低

### 2. 選對第一個專案
- 選「高頻 + 低風險 + 有資料」的任務
- 不要選「核心業務 + 錯不得 + 沒資料」的任務

### 3. 人比工具重要
- 要有一個人「負責」這個專案（不是兼著做）
- 要有使用者願意配合測試和回饋

### 4. 先求有效再求完美
- 第一版不需要完美，能跑就好
- 上線後持續收集 feedback 再改進

## Phase 0：準備期（1-2 週）

### 0.1 找到你的第一個專案

**推薦的 Quick Win 任務**：

| 任務類型 | 範例 | 為什麼適合 |
|----------|------|-----------|
| 內部知識問答 | 員工問 SOP/FAQ | 錯了不會死、資料現成 |
| 文件摘要 | 會議記錄摘要、合約摘要 | 有明確輸入輸出 |
| 分類/標籤 | 客服工單分類、郵件分類 | 可評測、可比較 |
| 草稿生成 | 回覆草稿、文案草稿 | 人工覆核把關 |

**不推薦的第一個專案**：

| 任務類型 | 為什麼不適合 |
|----------|-------------|
| 全自動客服 | 錯誤成本高、需要大量整合 |
| 財務/法務決策 | 合規風險高 |
| 需要大量整合的 | 複雜度高、變數多 |

### 0.2 過 20 題 Checklist

打開 [評估表：導入前必問 20 題](評估表_導入前必問20題.md)，確認：
- 問題定義清楚
- 有資料可用
- 有人負責

### 0.3 準備資料

- 收集 50-100 筆範例資料（做測試用）
- 整理成 AI 可讀的格式（文字檔、CSV...）
- 確認沒有敏感資料，或已經脫敏

## Phase 1：PoC 驗證（2-4 週）

### 1.1 目標

> 用最小成本驗證「AI 能不能做到」，不需要完美，只需要證明可行。

### 1.2 PoC 怎麼做

**選項 A：No-Code / Low-Code（推薦新手）**

| 工具 | 適合 | 優點 |
|------|------|------|
| ChatGPT + GPTs | 簡單問答、摘要 | 免開發 |
| Claude Projects | 知識問答 | 可上傳文件 |
| Dify / Flowise | RAG 應用 | 視覺化編排 |
| Make / Zapier + AI | 自動化流程 | 整合現有工具 |

**選項 B：Low-Code + API**

| 工具 | 適合 | 優點 |
|------|------|------|
| LangChain + Streamlit | RAG、Agent | 彈性高 |
| Vercel AI SDK | Web 應用 | 部署快 |

### 1.3 PoC Gate（過關條件）

- [ ] 在 50+ 筆測試資料上，成功率 > 70%
- [ ] 錯誤可以被識別（知道什麼時候會錯）
- [ ] 使用者覺得「有用」（主觀但重要）
- [ ] 成本可接受（算一下一個月要花多少）

### 1.4 PoC 失敗怎麼辦

| 問題 | 對策 |
|------|------|
| 準確率太低 | 檢查資料品質、換 prompt、換模型 |
| 不知道什麼時候會錯 | 加信心閾值、加引用來源 |
| 成本太高 | 換小模型、加快取、減少呼叫 |
| 使用者不想用 | 重新理解需求、調整功能 |

## Phase 2：Pilot 試運行（4-8 週）

### 2.1 目標

> 在真實環境中小規模測試，收集真實 feedback，準備上線。

### 2.2 Pilot 範圍

- 選 1-2 個部門或 5-10 個使用者
- 限定使用場景（不是全開放）
- 明確告知「這是測試版」

### 2.3 Pilot 要做的事

1. **部署到可用環境**
   - 不能只在本機跑
   - 至少部署到內網或雲端

2. **建立監控**
   - 記錄每次輸入和輸出
   - 記錄使用者 feedback（好/不好）
   - 追蹤錯誤案例

3. **收集 Feedback**
   - 每週和使用者開會
   - 收集「什麼好用、什麼不好用」
   - 收集「錯誤案例」用來改進

4. **迭代改進**
   - 根據 feedback 調整
   - 優化 prompt、補資料、調流程

### 2.4 Pilot Gate（過關條件）

- [ ] 在真實使用中，滿意度 > 基準線
- [ ] 錯誤率可追蹤，且有改進趨勢
- [ ] 使用者願意繼續用（不是被迫用）
- [ ] 維運成本可接受
- [ ] 權限和資安審核通過

---

## Phase 3：Production 上線

### 3.1 目標

> 正式上線，成為日常工作的一部分。

### 3.2 上線前 Checklist

**功能面**：
- [ ] 功能穩定，沒有 show-stopper bug
- [ ] 效能符合要求（延遲、吞吐量）
- [ ] 有錯誤處理和 fallback

**安全面**：
- [ ] 權限控管到位
- [ ] 資料不會外洩
- [ ] 有審計日誌

**維運面**：
- [ ] 有監控和告警
- [ ] 有回滾方案
- [ ] 有人負責維護

**使用者面**：
- [ ] 使用者培訓完成
- [ ] 有使用手冊/FAQ
- [ ] 有回報問題的管道

### 3.3 上線後

1. **持續監控**
   - 每天看 dashboard
   - 異常時立刻處理

2. **持續收集 Feedback**
   - 每週/每月 review
   - 持續改進

3. **擴展範圍**
   - 成功後再擴展到更多部門/場景
   - 用相同方法論做下一個專案

## 常見問題

### Q：沒有技術人員怎麼辦？
A：
1. 用 No-Code 工具（GPTs、Dify）
2. 找外部顧問做 PoC
3. 培訓內部人員

### Q：預算很少怎麼辦？
A：
1. 先用免費額度（OpenAI、Claude 都有）
2. 用開源模型（Llama）+ 免費雲端（Colab）
3. 選最小範圍的 PoC

### Q：老闆說要快怎麼辦？
A：
1. 先做一個超小的 demo（1 週內）
2. 讓老闆看到可能性
3. 再爭取時間做完整的 PoC

### Q：失敗了怎麼辦？
A：
1. 失敗很正常，重要的是學到什麼
2. 記錄失敗原因，避免下次再犯
3. 換一個更適合的專案重新開始
