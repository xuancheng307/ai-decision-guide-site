# AI 導入前必問 20 題

> 在開始任何 AI 專案之前，先過一遍這份 checklist。
> 回答「否」的項目不代表不能做，但代表需要額外處理。

---

## A. 業務與目標（5 題）

### 1. 問題定義清楚嗎？
- [ ] 能用一句話描述要解決的問題
- [ ] 已拆解成具體的流程和任務
- 否 → 先做流程拆解，不要直接跳到 AI

### 2. 成功指標（KPI）定義了嗎？
- [ ] 有明確的量化目標（準確率、時間、成本...）
- [ ] 有基準線（現在的表現是多少）
- 否 → 沒有 KPI = 無法判斷成功與否

### 3. 錯誤的代價有多大？
- [ ] 已評估錯誤會造成的損失（金錢、客訴、法律...）
- [ ] 錯誤容忍度：____%
- 高代價 → 必須有 human-in-the-loop

### 4. 有預算和資源嗎？
- [ ] 有明確的預算範圍
- [ ] 有人力可以維護（不是做完就不管）
- 否 → 重新評估專案規模

### 5. 有 sponsor / 決策者嗎？
- [ ] 有人能拍板決定
- [ ] 有人會用這個系統（不是做給沒人要用）
- 否 → 先找到 sponsor

---

## B. 資料與治理（5 題）

### 6. 資料在哪裡？格式是什麼？
- [ ] 知道資料存在哪些系統
- [ ] 知道資料格式（結構化/非結構化）
- 否 → 先做資料盤點

### 7. 資料品質如何？
- [ ] 資料是最新的（不是 3 年前的）
- [ ] 資料是正確的（沒有大量錯誤）
- [ ] 資料是完整的（沒有大量缺失）
- 否 → 先做資料清理

### 8. 資料量夠嗎？
- [ ] 有足夠的資料做測試（至少 100+ 筆）
- [ ] 有足夠的資料做評測
- 否 → 考慮先收集資料或用合成資料

### 9. 資料敏感性如何？
- [ ] 已分類資料敏感等級（公開/內部/機密/個資）
- [ ] 知道哪些資料不能送外部 API
- [ ] 有脫敏/遮罩方案（如需要）
- 否 → 先做資料分級

### 10. 權限控管怎麼做？
- [ ] 知道誰可以看什麼資料
- [ ] 有辦法在 AI 系統中實現權限控管
- 否 → 這是重大風險，必須處理

---

## C. 技術與架構（5 題）

### 11. 能用外部 API 嗎？
- [ ] 公司政策允許使用外部 AI API
- [ ] 資料可以送到外部（或有私有部署方案）
- 否 → 只能用自架模型，成本會提高

### 12. 需要整合哪些系統？
- [ ] 列出要整合的系統清單
- [ ] 確認這些系統有 API 或可以整合
- 整合多 → 複雜度高，建議先做獨立 PoC

### 13. 延遲要求是多少？
- [ ] 定義可接受的回應時間
- [ ] 實時（< 1秒）/ 準實時（< 10秒）/ 批次
- 要求高 → 需要考慮快取、小模型、邊緣部署

### 14. 有評測方案嗎？
- [ ] 知道怎麼評測 AI 的表現
- [ ] 有測試集或評測方法
- 否 → 沒有評測 = 無法改進

### 15. 有監控方案嗎？
- [ ] 知道上線後怎麼監控
- [ ] 能追蹤每次錯誤的原因
- 否 → 上線後會變黑箱

---

## D. 風險與合規（5 題）

### 16. 幻覺風險怎麼處理？
- [ ] 已評估幻覺的影響
- [ ] 有緩解方案（引用來源、信心閾值、人工覆核）
- 否 → 參考 [瓶頸卡：幻覺與引用](../40_BOTTLENECKS_瓶頸與風險/Hallucination_Grounding.md)

### 17. Prompt Injection 風險怎麼處理？
- [ ] 已評估惡意輸入的風險
- [ ] 有輸入過濾/輸出檢查機制
- 否 → 參考 [瓶頸卡：工具風險](../40_BOTTLENECKS_瓶頸與風險/PromptInjection_ToolRisk.md)

### 18. 有合規要求嗎？
- [ ] 已確認產業法規（個資法、GDPR、金融法規...）
- [ ] AI 使用符合法規要求
- 否 → 先確認法規，避免事後被迫下架

### 19. 有記錄和可追溯性嗎？
- [ ] 能記錄每次 AI 的輸入和輸出
- [ ] 能追溯每個決定的原因
- 否 → 法規或稽核可能要求這個

### 20. 有回滾方案嗎？
- [ ] 如果 AI 出問題，能快速切回人工
- [ ] 有緊急關閉機制
- 否 → 上線前必須準備
