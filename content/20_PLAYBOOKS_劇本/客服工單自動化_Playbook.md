# 客服工單自動化 Playbook

> **目標**：自動分類客服工單、路由到正確部門、提供回覆建議，提升客服效率。

---

## 適用場景與前提條件

### 適用場景

- [x] 客服工單自動分類
- [x] 優先級自動判斷
- [x] 智能路由到對應部門/人員
- [x] 回覆建議（RAG-based）
- [x] 常見問題自動回覆

### 前提條件

| 條件 | 說明 | 檢查方式 |
|------|------|---------|
| 歷史工單 | > 1,000 筆有標籤資料 | 資料匯出 |
| 類別定義 | 明確的分類體系 | 文件化 |
| 知識庫 | FAQ / SOP 文件 | 文件清單 |
| 人工覆核 | 可設定覆核流程 | 確認流程 |

## 分步實作指南

### Step 1：分類系統設計

#### 1.1 類別定義

```yaml
# 範例類別體系
level_1:  # 主類別
  - 技術問題
  - 帳務問題
  - 退換貨
  - 產品諮詢
  - 投訴建議

level_2:  # 子類別（可選）
  技術問題:
    - 登入問題
    - 功能異常
    - 安裝問題
```

#### 1.2 分類方法選擇

[F] 較小的微調 LLM 在文本分類任務上持續且顯著優於較大的 zero-shot prompted 模型[^CLS_FineTuneVsZeroShot2024]。

| 方法 | 適用場景 | 精度 | 成本 |
|------|---------|------|------|
| **Zero-shot LLM** | 快速啟動、類別常變 | 中 | API 費用 |
| **Few-shot LLM** | 有少量範例 | 中-高 | API 費用 |
| **Fine-tuned 小模型** | 大量歷史資料 | 最高 | 訓練成本 |
| **Embedding + Classifier** | 需要高效 | 高 | 低 |

[F] 在 "tens-of-shot" 情境下，小型 LLM embedding + logistic regression 的效能等於或優於大型 LLM[^CLS_LogisticRegression2024]。

#### 1.3 分類 Prompt（Zero-shot）

```
你是客服工單分類助手。請根據工單內容判斷：
1. 問題類別：[技術問題/帳務問題/退換貨/產品諮詢/投訴建議]
2. 優先級：[緊急/高/中/低]
3. 信心度：[高/中/低]

工單內容：
{ticket_content}

請用 JSON 格式回答：
{"category": "...", "priority": "...", "confidence": "..."}
```

### Step 2：優先級判斷

#### 2.1 優先級規則

| 優先級 | 判斷依據 | 範例 |
|--------|---------|------|
| **緊急** | 服務中斷、安全問題 | 無法登入、資料外洩 |
| **高** | 功能無法使用 | 訂單無法提交 |
| **中** | 功能異常但有替代方案 | 匯出功能失敗 |
| **低** | 諮詢、建議 | 功能建議 |

#### 2.2 關鍵詞輔助

```yaml
urgent_keywords:
  - 緊急
  - 無法使用
  - 系統掛了
  - 資料遺失

high_keywords:
  - 錯誤
  - 失敗
  - 不能
```

---

### Step 3：路由邏輯

#### 3.1 路由規則

```python
# 偽代碼
def route_ticket(category, priority, confidence):
    # 低信心度 → 人工
    if confidence == "低":
        return "人工分類"

    # 路由映射
    routing_map = {
        "技術問題": "技術支援部",
        "帳務問題": "財務部",
        "退換貨": "物流部",
        "產品諮詢": "銷售部",
        "投訴建議": "客服主管"
    }

    # 緊急升級
    if priority == "緊急":
        return routing_map[category] + " (升級主管)"

    return routing_map[category]
```

{ticket_content}

## 常見陷阱與修法

| 陷阱 | 症狀 | 修法 |
|------|------|------|
| **類別定義不清** | 分類不一致 | 明確定義、範例文件 |
| **類別重疊** | 多類別高信心 | 合併類別或建立優先級 |
| **長尾類別** | 罕見類別效果差 | 歸入「其他」、人工處理 |
| **信心度校準不準** | 高信心度但錯誤 | 收集回饋、重新校準 |
| **回覆生硬** | 客戶體驗差 | Few-shot 範例、語氣調整 |

| 階段 | 指標要求 | 檢查項目 |
|------|---------|---------|
| **PoC → Pilot** | 分類準確率 > 75% | 200 筆測試 |
| **Pilot → Prod** | 分類準確率 > 85%, 採用率 > 50% | 1000 筆 + 客服回饋 |
| **Prod 維護** | 準確率變化 < -5% | 持續監控 |
